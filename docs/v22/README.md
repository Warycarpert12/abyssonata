# v22: проверка

Снимки «было (main) / стало (v22)» — `*.jpg` в этой папке. Скрипты проверки — `qa/` (в репозитории они только здесь:
корневая папка `qa/` по `.gitignore` остаётся на ПК). Скриптам нужен Playwright с Chromium и собранный сайт
(`python build_site.py`, затем любой статический сервер над `_site/`); адрес страницы — с `?qa`.

| Скрипт | Что проверяет |
|---|---|
| `move_check_split.mjs <web эталона> <web ветки>` | баланс мира: 8 миров × 40 игровых минут, события, численность, отпечаток |
| `mix_check.mjs <audio.js эталона> <audio.js ветки>` | нормализация и разбор записей — побитово как в main |
| `perf_profile.mjs <адрес> [сек] [замедление CPU]` | профиль кадров (CDP): долгие кадры, сборка шейдеров, распаковка звука, GC |
| `fish_check.mjs`, `hover_check.mjs`, `quality_check.mjs` | рыбы не в острове, подпись при наведении (время, когда зверь вне кадра или под панелью, не считается), качество картинки |
| `desktop_check.mjs`, `mobile_check.mjs`, `ios_check.mjs` | ПК, телефон (касания), эмуляция iPhone и «старого Safari» (адрес — тоже с `?qa`) |
| `shots.mjs` | снимки для сравнения |

## Итоги

**Баланс** (`move_check_split.mjs`): 8/8 миров совпадают с main после каждого коммита.

**Фризы** (`perf_profile.mjs`, 3 мин, Chromium без видеокарты — картинка рисуется программно, поэтому почти все
кадры здесь дольше 50 мс; показательна «работа кадра» — JS внутри кадра):

| | main | v22 (первая часть) | v22 (после контрольного прогона) |
|---|---|---|---|
| обычная скорость, после первых 15 с: самая долгая работа кадра | 725 мс | 18 мс | 16 мс |
| — кадров с работой дольше 50 мс | 34 | 0 | 0 |
| — шейдеров собрано посреди игры | 32 | 0 | 0 |
| CPU ×4, случайный мир: самая долгая работа кадра | 638 мс | 57–85 мс (2 прогона) | 58–132 мс (2 прогона) |
| — кадров с работой дольше 50 мс | 120 | 6–8 | 11–20 |
| — шейдеров собрано посреди игры | 29 | 0 | 0 |

Мир каждый раз случайный, и при CPU ×4 прогоны одной и той же сборки различаются в 2–3 раза. Поэтому для сравнения
есть ещё прогоны с одинаковым миром (`&seed=7&rseed=7`, 150 с, CPU ×4, по 2 прогона каждой сборки):

| одинаковый мир, CPU ×4 | main | v22 (первая часть) | v22 (после контрольного прогона) |
|---|---|---|---|
| медиана работы кадра | 34–35 мс | 30–31 мс | 32 мс |
| самая долгая работа кадра | 645–700 мс | 71–99 мс | 72–117 мс |
| кадров с работой дольше 50 мс | 38–55 | 16–23 | 18–23 |
| шейдеров собрано посреди игры | 22 | 0 | 0 |

**Рыбы в острове** (`fish_check.mjs`, 3–5 раскладок × 15 мин): main — рифовые стайки 0.39%, стайки у острова 31%;
v22 — 0 из 2.1 млн проверок (после контрольного прогона, с ускоренным рельефом, — снова 0 из 1.3 млн).

## Контрольный прогон (вторая часть v22)

Новые скрипты:

| Скрипт | Что проверяет |
|---|---|
| `gate_ui_check.mjs` | пока открыт вход — интерфейс мира скрыт и не ловит нажатия/наведение; после входа проявляется (ПК, телефон, iPhone, слабый ПК с долгим первым кадром) |
| `layout_check.mjs` | панели и нижний ряд кнопок не налезают друг на друга: 8 экранов от iPhone SE до 1920×1080 |
| `combo_check.mjs` | сочетания: пауза + время суток / слежение / клик по журналу / качество / «сон» вкладки, частый пробел |
| `audio_check.mjs <адрес> [&lite=1]` | щелчки и обрывы звука (запись выхода AudioWorklet'ом): пауза/«Дальше», «сон» вкладки |
| `memory_check.mjs <адрес> [мин]` | рост памяти: куча, геометрии, текстуры (отдельно — кости зверей), шейдеры, обработчики, звуки, DOM |
| `terrain_check.mjs <visual.js эталона> <visual.js ветки>` | рельеф (`islandH`) — побитово как в main на 2.4 млн точек, и во сколько раз быстрее |
| `rotate_check.mjs` | телефон: поворот экрана, кнопка «На весь экран», вход, пауза, подсказка |
| `rename_check.mjs` | новое имя на странице, в manifest.json и credits.html; настройки переезжают со старых ключей `om.*` |

Что найдено и исправлено (по коммиту на каждое):
- нижний ряд кнопок (с «Паузой» и «Линзой») налезал на журнал на ПК 1280×720, iPad и телефонах;
- вход стал дольше на ~2.5 с (записи распаковывались по одной) — записи, без которых не войти, снова распаковываются сразу;
- пауза + кнопка времени суток: небо и часы не менялись, пока пауза;
- рельеф (`islandH`) считается в 1.6–1.8 раза быстрее, результат побитово тот же — меньше работы кадра на слабых;
- пауза щёлкала: звук обрывался на полной громкости (край 1.9–3.8 от средней громкости) — теперь затихает за 60 мс (0.00);
- прыжки рыб, летучие рыбы и ушедшие звери оставляли в видеопамяти кости и крылья (10 прыжков — +30 текстур) — теперь 0;
- на слабом устройстве (первый кадр после «Войти» дольше 1.4 с) карточка входа исчезала разом, без частиц — теперь
  рассыпается до конца (ход анимации копится по кадрам).

**Память** (`memory_check.mjs`, 10 мин живого мира): куча JS не растёт (20.4 → 17.7 МБ со 2-й минуты до конца), геометрий
110 → 113, шейдеров 47 → 48, обработчиков событий на window/document 24/2 всё время, звуков одновременно 11–25, DOM растёт
только вместе с журналом до его предела (40 строк). Текстуры идут за зверями: приплыл косяк — +48 текстур костей, уплыл —
−48 (до исправления они оставались навсегда); остальные текстуры 76 → 77. В main за те же 10 минут: текстур 26 → 137 и
шейдеров 35 → 40 (догружались и собирались посреди игры), кости ушедших зверей не освобождались.

**Звук** (`audio_check.mjs`): 3 паузы подряд — край остановки и возобновления 0.00 (было 1.9–3.8), в облегчённом
режиме тоже; «сон» вкладки — без разрывов и скачков волны. Пока вкладка свёрнута, мир стоит, а звук природы идёт дальше
(так было и в main).

**Кадры** — см. таблицы выше: после контрольного прогона долгих кадров не прибавилось (одинаковый мир — те же 18–23
кадра дольше 50 мс при CPU ×4, что и в первой части).

Оставшиеся кадры дольше 50 мс (только при CPU ×4) — отрисовка самой сцены three.js (много отдельных объектов),
подготовка материалов только что появившегося зверя и сборка мусора. Убрать их — отдельная работа (объединение
одинаковых рыб и частиц в один объект отрисовки), в этот PR не входит.

**Телефон и iPhone** (эмуляция в Chromium): вход, листание, пауза, подсказки, поворот, «На весь экран», «старый Safari» —
всё проходит. Настоящих устройств и WebKit в облаке нет.
