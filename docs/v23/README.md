# v23, этап 1: баги с телефона

Скрипты проверки — `qa/` в этой папке. Им не нужен Playwright: безголовый Edge по протоколу отладки (`qa/cdp.mjs`).
Страница — с локального сервера (`python serve.py` или собранный `_site/` под любым статическим сервером).

| Скрипт | Что проверяет |
|---|---|
| `fullscreen_check.mjs <адрес>` | телефон: «Войти» → полный экран, размер окна приходит с задержкой; режим «как в Edge» — окно выше экрана на высоту панели браузера. Кнопки, журнал и «Обитатели» — в пределах экрана |
| `layout_cmp.mjs <адрес main> <адрес ветки>` | раскладка панелей и кнопок как в main на 17 экранах; выход из полного экрана и поворот — картинка по окну |
| `heading_check.mjs <адрес> [минут=25]` | для всех зверей, птиц и рыб: куда смотрит нос модели и куда она движется; кадры «задом» (больше 90°) и «боком» |

## Баг А — интерфейс пропадал после «Войти» (Huawei Pura 70 Ultra, Edge 153)

По фото с телефона: после входа страница получалась выше экрана примерно на высоту панели адреса Edge (~52 px из
~376): «Обитатели» уходили вниз, журнал, пауза и время суток — за край; свернёшь «Обитателей» — пропадают совсем.
Повторено в эмуляции (окно 807×428 при экране 807×376).

- `?debug=1` — поверх экрана размеры окна, видимой области и экрана, плотность, ориентация, полный экран, safe-area,
  высоты 100vh/dvh/svh/lvh, сработавшие медиа-условия, где каждый блок интерфейса (виден / за краем) и последние события
  размера.
- Правка: высота страницы — то, что реально видно (меньшее из окна, видимой области и, в полном экране на сенсорном,
  самого экрана); пересчёт по resize, visualViewport.resize, fullscreenchange, orientationchange и ещё через 0.3 и 1 с.

| `fullscreen_check` | main | ветка |
|---|---|---|
| окно выше экрана (как в Edge), размер через 0 / 0.7 / 1.5 с | 3 провала: низ кнопок 418 при экране 376 | 3/3 в пределах экрана |
| обычный телефон | 3/3 | 3/3 |

`layout_cmp`: на 17 экранах (5 телефонов и планшет, 11 окон ПК) раскладка как в main; полный экран, выход из него и
поворот — картинка и кнопки по окну.

Не проверено: настоящий телефон (жду снимков с `?debug=1`), другой браузер на том же телефоне.

## Баг Б — морской лев плыл задом наперёд

Причина: догнав свою точку, лев считался «лежащим» и поворачивался мордой к морю, а точка ещё плыла к пляжу — он
двигался к берегу хвостом вперёд, бывало больше минуты. Теперь «лежит» только тот, кто стоит на месте (тело
движется медленнее 0.3 м/с); пока движется — смотрит по ходу и на суше переваливается. Только `visual.js`.

`heading_check`, 4 мира × 25 минут, шаг 1/60 с; доля кадров движения, где нос смотрит назад (больше 90°):

| вид | main | ветка |
|---|---|---|
| морской лев | **12.77%** (выходит на берег: до 55 с подряд, угол ~177°, 3 м/с) | **0.10%** (медленный дрейф ~0.5 м/с) |
| кит, баклан, пеликан, рои креветок | 0.5–1.1% | 0.5–0.7% |
| остальные (дельфин, косатка, акула, скат, черепаха, птицы, рыбы косяка) | ≤ 0.1% | ≤ 0.1% |

У кита, баклана и пеликана это углы около 90° на малой скорости (разворот, посадка на камень, дрейф на воде), не
«задом». У медузы, звезды и осьминога «носа» нет, краб бегает боком — по замыслу. Числа других видов между прогонами
немного разные: картинка и мир в браузере делят один генератор случайных чисел.

**Баланс** (`docs/v22/qa/move_check_split.mjs`): 8/8 миров совпадают с main после каждого коммита.
